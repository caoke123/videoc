# 标准视频制作流程（standard-video-v2）

所有新视频制作请求统一按本流程执行。视频形式和场景可以变化；默认生成执行服务为 **AutoDL API**。素材要求由每个镜头实际展示的商品状态、动作、宣称及 AutoDL 输入决定；桌面、车内、4S 店、文创店等场景名称本身不触发额外素材或审批。无限画布不直接调用模型，也不承担合成；人工在画布里搭建的生成请求交给本机执行器（任务 `canvas-<画布id>`），与 Codex 自动化共用同一个执行器、同一套任务数据。

## 全流程

| 顺序 | 阶段 | 产出 | 完成条件 |
|---|---|---|---|
| 0 | 接收与证据盘点 | `brief.json` 初稿、原始素材清单、类目事实与未知项 | 明确产品/SKU、受众、平台、时长、比例、使用场景、可证实卖点、禁止宣称；读项目规则和类目 profile。原始文件原样保留在 `assets/source/`。 |
| 1 | 编剧与镜头拆解 | `creative-direction.md`、口播/旁白全文、逐镜头脚本和 `shot-plan.json` | 先写创意与脚本，再定镜头时长、动作、景别、对白、镜头结束状态和所需视觉素材。产品事实不得靠想象补全。 |
| 2 | 最小素材包 | 用户商品原图及本批次实际使用的其他证据；按需的参考图、关键帧和可复用资产 | 对每镜头列出实际入参及角色。仅在安装/佩戴、物理交互、特定人物或场景连续性、复杂构图、事实宣称或服务商输入需要时补图。可以只用用户原图；不要求逐镜头出分镜，也不要求生成独立资产图。新图保存在 `assets/generated/`，候选构图不冒充商品真值。 |
| 3 | AutoDL 提示词与批量预检 | 每镜头最终提示词、对白、参考图顺序、音频顺序、时长和工作流 | 从任务文件机械检查路径、SKU 对应、参考图角色、音频可访问地址、参数、时长及重复任务 ID；由人工一次查看本批次的创意和必要候选。仅当生成图要提升为商品身份、安装/佩戴或其他长期复用的权威资产时，单独自检并取得人工批准。 |
| 4 | AutoDL API 生成 | AutoDL 任务 ID、状态、版本化结果 | 一次预检全部待生成镜头，一次授权后通过本机执行器提交、轮询和落盘。浏览器和无限画布不直接调用模型接口。材质或人物一致性敏感的商品先用 `mode: "probe"` 只提交 1 个镜头，人工确认后再提交其余镜头。已有任务编号的镜头跳过，失败不自动重试；提交未得到 AutoDL 确认的镜头标为“待核对”，不自动重发。每次运行保存独立结果，不覆盖旧版本并记录操作人、提示词快照、参考素材、参数、任务 ID 和结果。 |
| 5 | 审片与交付 | 自检记录、人工审核状态、剪辑/交付产物 | 新图/视频先作为候选；自检不替代人工审核。未批准不得标记为正式成片。按项目默认路线交付可编辑的剪映专业版草稿；仅在明确需要技术预览时使用 HyperFrames。未包含配音、缺镜头或未解决的时间线缺口要明确列出。 |

## 耗时记录与审查边界

每个阶段在 `run-log.jsonl` 写入带时间戳的开始、完成或阻塞事件，并记录阻塞原因；生成阶段分别记录提交、远端完成和本地下载时间。复盘时据此区分素材制作、等待人工决定、服务商排队、下载和剪辑耗时。

提交前集中做一次镜头级检查：产品身份、实际要展示的使用状态或动作、宣称证据、提示词与参考图、时长和工作流。仅镜头表现安装/佩戴时才要求相应状态证据；车内但手持或独立摆放的商品不因此要求安装图。人审针对新权威资产、存在争议的视觉候选和最终成片，不为每个中间文件重复设闸。单个镜头失败时记录失败并继续其他镜头；重试由人工决定。

| 镜头实际需要 | 增加的素材或检查 |
|---|---|
| 只展示商品外观 | 商品原图和可证实文案；不强制人物图、场景图、分镜图或安装图。 |
| 商品与人、道具或环境发生特定物理关系 | 只补足该关系所需的参考或关键帧；人工一次查看本批次有争议的构图。 |
| 表现商品已安装或佩戴 | 对应 SKU 的批准状态参考；按类目核对接触、比例和空间关系。 |
| 使用特定真人、店铺、装修或跨镜头固定角色/空间 | 在确实需要还原或保持连续时提供身份/场景参考；普通泛化场景不需要专门审批。 |
| 使用事实性卖点、功效或安全宣称 | 提供可核对的事实依据；没有依据则改文案，不额外生图证明。 |

通用的商品身份核对和批量技术预检始终保留。付费提交只确认一次本批次范围；同一候选不得因复制、改名或进入画布而再次触发人工审批。

## 任务内目录与命名

```text
production/jobs/<job-id>/
  brief.json
  creative-direction.md
  shot-plan.json
  request-plan.json
  canvas-layout.json         # 仅保存人工调整过的布局
  run-log.jsonl
  assets/
    source/                 # 用户原件和外部原始参考，只读保留
    generated/              # 按需创建，存候选参考、关键帧或合成图
    approved/               # 按需创建，存人工批准的权威衍生资产
  audio/brief/seed-audio-1.0.md  # 有配音交接需求时创建
  renders/runs/<shot-id>/<task-id>.mp4
  renders/preview/           # 拼接/审阅版，不覆盖单镜头原片
```

**资产只引用、不复制**：SKU 原图、批准的安装态图、材质参考等在 `production/assets/`（`products/<sku_id>/`、`material-references/`、`characters/approved/`）中只有一份；任务的 `ref_images` 写 `library:products/<sku_id>/source/product-front.png` 这样的引用，提交时由执行器读取。上传按 sha256 判定：内容已在资产库就直接引用，同一任务内相同内容只存一份（`assets/source/<sha前12位>-名称`），不再产生带时间戳的副本。`GET /api/jobs/<id>/validate` 可在提交前机械检查镜头 id、参考图、时长和配音 URL；`node autodl-video-workbench/scripts/report-duplicate-assets.mjs` 只读列出现有重复素材。

以上是可用路径，不是逐项建档清单。新任务只先创建 `assets/source/` 和必要的任务文件；其他目录在产生真实文件时建立。已有任务的兼容路径可以保留。需要把外部创作素材上传到本地工作台时，上传后复核 `shot_id` 引用是否仍指向原计划文件。

## AutoDL 默认执行合同

```text
任务资产（图片、音频） + 最终提示词
  → 本机执行器预检
  → AutoDL H3 提交
  → 任务 ID / 轮询
  → 版本化 MP4 落盘
  → 人工审片与交付
```

- 本机执行器是唯一提交者，保管 AutoDL ComfyUI Token；任何浏览器节点均不得保存 Token 或直接请求 AutoDL。
- 每个镜头在 `request-plan.json` 中记录 `workflow_id`、`ref_images[]`、`ref_audio[]`、时长、分辨率、seed 与最终提示词。音频先转为 AutoDL 可读取的 URL，再填入 `ref_audio_0...ref_audio_2`。
- 默认使用 H3 多图多音频工作流；旧工作流仅为已有任务兼容保留。预检限制由工作流契约确定，当前目标为最多 9 张图片、3 段音频、单条成片 1–15 秒。
- 任务状态只来源于 AutoDL 返回的 task ID 和轮询结果。没有 task ID 的镜头一律视为“未提交”。

## 可选任务视图

- **参考素材节点**：仅显示本批次实际引用的人物/SKU/场景/材质图，标出参考角色；来源图与生成候选区分开。
- **分镜图节点**：仅在有实际分镜或关键帧时显示，可连到对应镜头。
- **资产图节点**：仅在有实际可复用资产时显示版本和审核状态。
- **镜头提示词节点**：每个镜头一张；提示词、对白、时长和参考图顺序能在侧栏人工编辑并留日志。
- **视频结果节点**：生成结果存在后显示该镜头当前版本；历史版本在侧栏或运行记录查看。生成前的状态只显示在镜头节点上。整片文件存在后才显示总片预览节点。
- **连线**：素材/分镜/资产 → 对应镜头 → 该镜头结果；分镜镜头之间按播放顺序连接；总片节点汇集本次入片镜头。

任务视图从任务资料自动呈现，不作为额外人工排版工序；布局只存 `canvas-layout.json`，不写入 run-log。视图上的生成按钮只调用本机执行器。每个实际入参必须能追溯到使用它的镜头及生成版本；无关文件不进入主视图。

## 允许分支

- **UGC/TVC/主图视频**共享上述最小素材包；镜头数不决定分镜图数量。简单镜头可只有文字镜头卡，复杂镜头可提供单张或多张关键帧。
- **九宫格**按其交付形式准备总览和格内说明；它属于图像任务时不可误走 H3 视频工作流。之后要把九格转成视频，按实际镜头补齐必要入参和提示词，再提交视频生成。
- **纯产品或无真人形式**无需人物参考。任何形式均只归档和连接实际使用的素材，不创建空文件或占位节点。
- 形式专属限制写入 `production/formats/`，产品/场景真值写入 `production/categories/` 和对应 skill；不得另造一套顺序。
