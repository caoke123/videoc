# Ecommerce short-video production project

Use `.agents/skills/ecommerce-video-studio/SKILL.md` for product-video planning, original scripts and storyboards, realistic people, category selection, generation, review, and delivery. Every new video request follows `production/workflows/standard-video-production.md`: evidence and brief → script and shot plan → minimum required asset package → one batch preflight and authorized generation → review. Reference, storyboard, and reusable asset images are conditional outputs, not mandatory stages. The selected scene never creates a gate by itself; apply evidence rules to what each shot actually depicts, does, or claims. Infinite Canvas projects the job files automatically and is not an asset-preparation or approval gate. For seatbelt shoulder pads, also use `.agents/skills/seatbelt-video-studio/SKILL.md` and its product and vehicle constraints. Read the chosen category profile in `production/categories/` before generating images or video.

Production data lives under `production/`. Never overwrite original media in a job's `assets/source/`. Paid generation (AutoDL through the local runner, or legacy DFCine/GPU runs) requires explicit user confirmation. The local runner is the only submitter and the only holder of the AutoDL token; it has two entry points that share the same job data — Codex automation (job files, batch submit) and manual edits/generation in Infinite Canvas (task `canvas-<canvas id>`). Browsers never call AutoDL or store its token. Review is human-first; AI review and retries happen only on request.

Building or cloning a whole Infinite Canvas project (many nodes/connections/prompts at once) is much faster as one JSON document PATCHed to the local runner than as many individual node-by-node tool calls — use `.agents/skills/infinite-canvas-json-build/SKILL.md`.

For new H3 jobs, every generated shot must include audible, script-locked native dialogue or off-screen narration to guide performance and mouth movement; final audio may later be replaced. For post-production, use `.agents/skills/ecommerce-video-edit/SKILL.md`: the job remains the source of truth, ClipSkills decides the rough cut, and the primary handoff is an editable Jianying Pro draft. The user imports/opens it in Jianying, performs final fine editing, and manually exports. HyperFrames is optional, not the default assembly tool. Missing shots, voiceover, or uncovered timeline gaps must be reported, never silently removed. Do not call a preview or draft a final delivery before human review.

Voice generation is an external user step using Seed Audio 1.0: prepare a per-shot handoff with exact spoken text, speaker role, emotion, delivery/tone, timing, and target duration; do not call ElevenLabs or another TTS provider unless the user explicitly changes this policy. Import the user's generated audio before subtitle timing and draft assembly.

`production/assets/` is the shared cross-job library (characters/products/material-references/structure-references) — it holds only confirmed, reusable reference images, never generation-in-progress files. Candidate images, multi-round self-checks, and approval-discussion docs for the current job stay under that job's own `production/jobs/<job-id>/assets/`; never write them directly into `production/assets/`. Only after a human confirms an image should still be worth reusing across jobs does it get copied (never moved) into `production/assets/`, via the local runner's promote endpoint (`POST /api/jobs/:jobId/assets/promote`, same one the "收进素材库" button in Infinite Canvas uses) — sha256-deduped, so the same content is never copied twice. What lands in `production/assets/` should be the image plus at most a short identity/usage note, not the generation history.
